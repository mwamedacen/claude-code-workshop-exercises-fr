# Atelier 8 · Confier une tâche au cloud (10 + 30 min)

*Après le bloc 8 : où tourne un agent, le sandbox, partir vers le cloud (pousser d'abord, savoir ce qui voyage) et en revenir (`--teleport`, la pull request).*

**Mission.** Une session cloud réalise la carte D : chaque ligne de « Mes réservations » propose « Ajouter à mon agenda », un fichier de calendrier pour sa propre réservation, sans aucune donnée d'un collègue. Vous écrivez le plan, lancez la session et la suivez depuis votre téléphone ou le navigateur, puis rapatriez et vérifiez son travail.

**Départ.** Continuez depuis l'atelier 7 ou lancez `npm run checkpoint -- w8-depart`, puis `git push -u origin HEAD`. Référence finale : `final`. Si le test cloud de 09h00 a échoué (clé d'API, passerelle d'entreprise), travaillez en binôme sur le compte de votre voisin.

## Parcours principal · 32 min

Étapes 1 à 4 à 15h32 ; étapes 5 à 8 à 16h03, après « Pour aller plus loin ».

### 1. Le plan · 4 min

Passez en plan mode :

> Écris docs/carte-D.md, le plan de la carte D de BACKLOG.md : objectif, contrat (la route, les réponses 200, 403 et 404), fichiers autorisés, limites, contrôle par test/acceptation/carte-d.test.js, et la vérification dans le navigateur faite en local au retour. Ne code rien.

Relisez le plan, puis commitez-le.

**Attention :** laissez le `todo` du test de la carte D. Retiré maintenant, votre verrou `Stop` exigerait de réaliser la carte ici, en local.

### 2. Pousser · 1 min

`git status` doit être vide. Puis `git push`.

### 3. Confier · 3 min

Dans un terminal ordinaire, hors d'une session Claude :

```sh
claude --cloud "Réalise la carte D selon docs/carte-D.md : retire le todo du test, rouge puis vert, npm test, puis ouvre une pull request. Ne lance pas l'application."
```

Vous pouvez aussi envoyer la même consigne depuis claude.ai/code ou l'onglet Code de l'application Claude.

**Vérifiez :** la commande affiche le lien de la session. Sans la Claude GitHub App sur votre repo, Claude Code envoie une copie de votre repo à la session ; elle pousse sa branche avec votre connexion GitHub.

### 4. Prévoir · 2 min

Qu'est-ce qui va voyager ? Remplissez la colonne « Avant » : oui ou non.

| Élément | Avant | Après |
|---|---|---|
| `CLAUDE.md` du repo | | |
| Les skills de `.claude/skills/` | | |
| Le sous-agent `qa-visiteur` | | |
| Les hooks de `.claude/settings.json` | | |
| `.mcp.json` (Playwright) | | |
| Votre dossier `~/.claude` | | |
| Cette conversation | | |

### 5. Suivre · 6 min

Ouvrez la session sur votre téléphone ou sur claude.ai/code. Lisez le transcript et le diff. Cherchez dans le transcript un retour du hook `Stop` : il n'apparaît que si le verrou a bloqué Claude.

**Vérifiez :** le test de la carte D est passé du rouge au vert dans la VM ; d'après le transcript, vous savez si le verrou `Stop` a retenu Claude.

### 6. La pull request · 5 min

Ouvrez la pull request sur GitHub. Si la session n'a pas pu la créer, utilisez le bouton de création de pull request de la session sur claude.ai/code. Sa base doit être votre branche de travail ; sinon, changez-la.

**Vérifiez :** le diff ne touche que les fichiers autorisés par `docs/carte-D.md` ; dans le test, seul le `todo` a disparu.

### 7. Rapatrier · 6 min

`git status` doit être vide, sinon `--teleport` vous propose de mettre vos changements de côté. Puis lancez `claude --teleport` et choisissez la session : Claude Code vérifie le repo, récupère la branche poussée par la session et reprend la conversation. Il faut le même repo et une connexion claude.ai, sans clé d'API. Dans un autre terminal, lancez `npm test`, puis `npm run check -- final`.

**Vérifiez :** les tests sont verts ; connecté en tant que Camille, « Ajouter à mon agenda » télécharge un fichier qui s'ouvre dans votre agenda.

### 8. Le bilan · 5 min

Remplissez la colonne « Après » du tableau, avec une preuve pour chaque ligne. Lancez `/usage` et notez la part de votre forfait consommée par la session cloud.

**Vérifiez :** chaque « Après » s'appuie sur un fait observé dans la session ou dans le repo.

## À montrer à la fin

- [ ] `docs/carte-D.md` commité et poussé avant la session cloud.
- [ ] La pull request de la session, avec son diff relu.
- [ ] La branche rapatriée : `npm test` vert et `npm run check -- final`.
- [ ] Le tableau « Avant / Après » rempli.

## Si le groupe prend du retard

Travaillez en binôme sur une seule session cloud, ou suivez celle du formateur au projecteur pour les étapes 5 et 6. Gardez l'étape 7 sur votre machine.

## Pour aller plus loin

- **Niveau 2 :** activez `/sandbox` (macOS, Linux et WSL2) et relancez une demande qui écrit hors du repo.
- **Niveau 3 :** lancez `npm run qa:commande` sur la branche rapatriée, ou `/autofix-pr` sur la pull request si la Claude GitHub App est installée sur votre repo.
- **Encore du temps :** prenez une carte du `BACKLOG.md`.

**Checkpoint :** `npm run check -- final`.

Revérifiez l'accès au cloud de chaque compte avant la session.*
