# Lab 3 · Rules, a feature, a new look (70 min)

*After block 3: `CLAUDE.md`, `/init`, `/memory`, `/context`, reading a skill before installing it, and creating a project skill.*

**Mission.** Turn lab 2's mistakes into rules for Claude. Build “Salle libre maintenant” under those rules, change the app's appearance, then record that visual direction in a reusable skill.

**Start.** Continue your lab 2 work, or run `npm run checkpoint -- w3-depart`. Intermediate references: `w3-regles` and `w3-fonction`. Final reference: `w4-depart`.

## Core path · 55 min

### 1. Turn mistakes into project rules · 12 min

Run `/init`: Claude proposes an initial `CLAUDE.md` from the repo. Review it, then ask:

> Add a “Rules” section to CLAUDE.md based on our lab 2 mistakes: compare times correctly, calculate calendar days correctly, use the room's real capacity field, keep “my bookings” scoped to the right person, write a failing test before a fix, keep personal data out of exports, and do not edit data/floor-plan.json because it belongs to Facilities. Give one line per rule explaining what to do and why.

Open `/memory`, then `/context` to see what the session loads. The export found in lab 1 violates one rule:

> Bring the export into compliance with our personal-data rule, with a test that fails before the fix.

**Check:** `CLAUDE.md` has at least five rules with reasons; the export reveals no names or emails; the test turned green after being red.

### 2. Check in a new conversation · 3 min

Run `/clear`, then ask:

> What are our rules for times and calendar days? Answer without searching the code.

**Check:** Claude recalls the rules from `CLAUDE.md`. If its answer is vague, improve the rules instead of repeating them in every prompt.

### 3. The “Salle libre maintenant” card · 22 min

> **Goal:** I enter my group's size and see rooms free for the next hour, large enough, sorted from smallest to largest; those rooms light up on the plan.
>
> **Check:** for three people at 14:05, every proposed room has at least three seats, no meeting occupies it before 15:05, and the list is sorted by capacity.

Switch to plan mode:

> Read the “Salle libre maintenant” card in ateliers/W3.md. Propose a plan that cites the relevant CLAUDE.md rules and the tests to write before the code.

Review the plan, then let Claude implement the card. Check the app in the browser. If the real clock leaves no room free, restart with a simulated clock: `npm start -- --maintenant YYYY-MM-DDT14:05` (use today's date).

> Replay the card's check in the browser, take a screenshot of the plan, and commit after the tests pass.

**While Claude works:** predict an edge case (a room booked in 25 minutes or with too little capacity). **Check:** Claude's plan cites the time rule; tests went from red to green; the screenshot shows the proposed rooms on the plan.

### 4. A new look with an official skill · 12 min

Open `/plugin`, find `frontend-design` in Anthropic's official marketplace, and **read it before installing**:

> Show me the frontend-design skill description and instructions, including what it might ask to run. Do not install it yet.

After reading, install it with `/plugin install frontend-design@claude-plugins-official`, then ask:

> Use frontend-design to give Ma Place a clear, readable interface in light and dark themes without changing its behavior. Check the four buttons and “Salle libre maintenant” in the browser. Take before and after screenshots.

**Check:** the screenshots show a visible change; the actions still work; `npm test` passes. If the plugin is unavailable, describe your own visual direction to Claude and mark the plugin “to re-test.”

### 5. Make the look reusable · 6 min

> Interview me about which visual decisions to keep, then create a project skill called “charte”: colors, components, and rules for future interface changes.

**Check:** `.claude/skills/charte/SKILL.md` exists and its description says when to use it. Read its instructions before committing.
