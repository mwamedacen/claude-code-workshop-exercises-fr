# Atelier 5 · Trois fonctions en même temps (60 min)

*Après le bloc 5 : qui coordonne, l'orchestrateur et ses exécutants, les worktrees, une vérification par agent, le brief, le suivi des agents, l'intégration et la relecture par un regard neuf.*

**Mission.** Les cartes A, B et C de `BACKLOG.md` viennent des données de septembre. Trois sessions Claude les réalisent en parallèle, chacune dans son worktree. Vous fixez les limites, vous exigez les preuves et vous fusionnez.

**Départ.** `w5-depart`, chargé à 09h00 (voir « Ateliers du jour 2 » dans le README) ; sinon lancez `npm run checkpoint -- w5-depart`. Référence intermédiaire : `w5-fusion`, avec les trois briefs et trois branches `carte-a`, `carte-b`, `carte-c` prêtes à fusionner. Référence finale : `w6-depart`.

Chaque carte a son test d'acceptation dans `test/acceptation/`, en attente avec un `todo`. L'agent retire le `todo`, voit le test échouer, puis le fait passer sans changer l'assertion.

## Parcours principal · 45 min

### 1. La base · 3 min

Commitez tout votre travail : un worktree part d'un commit et ne reçoit pas vos fichiers non commités. Dans `.claude/settings.json`, `worktree.baseRef` vaut `"head"` : chaque worktree part de votre commit courant. Lancez `npm run check -- w5-depart`.

**Vérifiez :** `git status` n'affiche aucun changement ; le contrôle est vert.

### 2. Trois briefs · 5 min

Passez en plan mode :

> Rédige trois briefs sur le modèle de docs/briefs/modele.md, à partir des cartes A, B et C de BACKLOG.md : docs/briefs/carte-a.md, carte-b.md et carte-c.md. Fichiers autorisés : ceux que la carte exige, plus son test d'acceptation pour retirer le todo. Interdits : CLAUDE.md, BACKLOG.md, data/floor-plan.json, le test d'une autre carte, toute nouvelle dépendance. À rendre : la sortie rouge puis verte, une capture de l'écran dans captures/ (ignoré par Git), les fichiers modifiés.

Relisez les briefs et commitez-les avant l'étape 3 : un worktree créé avant ce commit ne les contient pas.

**Vérifiez :** plusieurs briefs autorisent `server/index.js` ou `web/js/panneau.js` : attendez-vous à des conflits à la fusion.

### 3. Trois sessions · 5 min

Ouvrez trois terminaux à la racine du repo et lancez `claude --worktree carte-a`, `claude --worktree carte-b` et `claude --worktree carte-c`, un par terminal. Donnez à chaque session son brief (`carte-b.md` et `carte-c.md` pour les deux autres) :

> Lis docs/briefs/carte-a.md et réalise la carte. Quand npm test est vert, commite sur ta branche, puis lance npm start en arrière-plan et donne-moi son adresse.

**Vérifiez :** `git branch` liste `worktree-carte-a`, `worktree-carte-b` et `worktree-carte-c`.

### 4. Suivre les preuves · 17 min

Passez d'une session à l'autre et répondez à leurs questions sur l'objectif. N'acceptez « c'est fini » qu'avec la preuve :

> Montre-moi la sortie de node --test test/acceptation/carte-a.test.js avant ton code, puis après, et la capture de l'écran.

Ouvrez vous-même chaque application à l'adresse donnée : chacune affiche sa branche dans l'en-tête. Lancez `/usage` et notez ce que consomment trois agents en parallèle.

**Pendant l'exécution :** `←` sur une invite vide passe une session en arrière-plan ; `claude agents` affiche alors vos sessions et leur état. Une session qui veut arrêter son serveur vous en demande la permission.

**Vérifiez :** chaque branche a son commit, son test vert et sa capture dans `captures/` ; les trois applications répondent sur trois ports différents. La ligne `ExperimentalWarning` de SQLite dans la sortie du test est sans conséquence.

### 5. Fusionner · 10 min

Quittez les trois sessions. À la question de Claude, **gardez le worktree** : le supprimer efface aussi sa branche et la carte avec elle. Dans votre terminal principal, sur votre branche de travail, fusionnez les cartes une à une, A, B puis C. Si vous êtes reparti de `w5-fusion`, les branches s'appellent `carte-a`, `carte-b` et `carte-c`.

```sh
git merge --no-edit worktree-carte-a
npm test
```

Ouvrez une session `claude` à la racine du repo pour la suite. Une fusion peut s'arrêter sur un conflit, le plus souvent dans `server/index.js`, `web/js/panneau.js` ou `web/style.css`. Dans ce cas :

> Résous ce conflit en gardant les deux côtés, chaque bloc avec son accolade fermante. Lance npm test, puis termine la fusion avec git add et git commit --no-edit.

Les tests sont verts, mais une interaction entre A et B reste cachée :

> Retire le todo de test/acceptation/fusion-a-b.test.js et lance-le. Explique pourquoi il échoue, corrige le code sans changer l'assertion, puis lance npm test et commite.

**Vérifiez :** le test A×B est passé du rouge au vert ; les trois fonctions sont visibles dans l'application ; `git status` n'affiche aucun changement.

**Attention :** si vous gardez un seul côté d'un conflit, une carte disparaît.

### 6. Relire · 5 min

Lancez une relecture de tout l'atelier avec `/code-review medium w5-depart...HEAD`, puis :

> Corrige un seul constat de cette relecture, celui qui a une preuve : un test qui échoue ou un comportement visible. Écris d'abord le test.

Si ce constat contredit un test d'acceptation, ne le corrigez pas : notez-le dans `BACKLOG.md` comme limite de la carte. Commitez.

**Vérifiez :** le constat est corrigé avec son test et `npm test` est vert, ou il est noté dans `BACKLOG.md`.

## À montrer à la fin

- [ ] Les cartes A, B et C fonctionnent dans l'application.
- [ ] Une sortie rouge puis verte et une capture par carte.
- [ ] Les conflits de fusion résolus en gardant les deux côtés.
- [ ] Le test A×B actif et vert, `npm test` vert.

## Si le groupe prend du retard

Réalisez les cartes A et B seulement : leur fusion et le test A×B sont l'essentiel. La carte C se montre au débrief. Pour vous entraîner à la fusion, `npm run checkpoint -- w5-fusion` crée les trois branches de référence.

## Pour aller plus loin

- **Niveau 2 :** sur la carte C, faites proposer deux solutions par deux sessions, puis demandez à une troisième de choisir à partir des tests et de l'écran, sans savoir qui a écrit quoi.
- **Niveau 3 :** lancez `/batch` sur d'autres cartes du backlog ; activez `/advisor` et comparez la qualité des vérifications.
- **Encore du temps :** prenez une carte du `BACKLOG.md`.

**Checkpoint :** `npm run check -- w6-depart` sur votre branche fusionnée.
