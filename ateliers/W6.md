# Atelier 6 · L'agent de recette (55 min)

*Après le bloc 6 : `claude -p` avec un schéma et deux plafonds, ce que charge `-p`, l'Agent SDK, la lecture de l'agent de recette, la connexion par abonnement et un bon constat.*

**Mission.** Un agent de recette visite Ma Place comme un utilisateur, avec Playwright, et rend un verdict prouvé sans toucher au code. Vous le lancez dans une session, puis par une commande, puis par un programme. Une régression volontaire doit faire passer son verdict au rouge.

**Départ.** Continuez depuis votre fusion de l'atelier 5 ou lancez `npm run checkpoint -- w6-depart`. Référence intermédiaire : `w6-commande`, après l'étape 3. Référence finale : `w7-depart`. Les dépendances de `qa/` sont installées depuis 09h00 ; sinon, lancez `npm ci --prefix qa`.

## Parcours principal · 42 min

### 1. Trois parcours · 4 min

> Écris qa/parcours.md : trois parcours de Ma Place, chacun avec l'action, le résultat attendu et la preuve à garder. 1. Camille Martin (e001) réserve un poste libre pour un jour futur. 2. Une réunion commencée depuis plus de 10 minutes sans arrivée signalée est libérée, et la salle se réserve de nouveau. 3. Pour deux personnes, la salle Garonne propose une salle plus petite et reste réservable. Indique en tête la commande de démarrage et la remise à zéro entre deux passages.

Démarrez l'application dans un autre terminal :

```sh
npm start -- --maintenant 2026-10-07T14:15
```

Notez l'adresse affichée. Si ce n'est pas `http://localhost:3000`, ajoutez `-- --url <adresse>` aux commandes `qa:commande` et `qa:programme`, et donnez l'adresse à Claude à l'étape 2.

**Vérifiez :** chaque parcours décrit l'écran et une preuve observable ; aucun ne cite une fonction du code.

### 2. Le sous-agent · 10 min

> Crée le sous-agent .claude/agents/qa-visiteur.md. Outils : Read, Grep, Glob et mcp__playwright, rien d'autre. Il suit qa/parcours.md dans l'application déjà lancée, ne modifie aucun fichier et range ses captures dans qa/rapport/. Pour chaque parcours, il rend ok, echec ou incomplet avec la preuve observée. Sans preuve, le parcours est incomplet.

**Attention :** une écriture dans `.claude/` demande toujours votre accord, même en accept edits.

Relisez le fichier, puis :

> Délègue le parcours 1 de qa/parcours.md à qa-visiteur et montre-moi sa preuve.

**Pendant l'exécution :** si Claude Code propose le serveur `playwright`, choisissez « Use this MCP server », puis acceptez les outils Playwright. Suivez les actions du navigateur dans le transcript.

**Vérifiez :** l'agent a réellement réservé dans l'application ; `git status` ne montre aucun fichier modifié par lui.

### 3. La commande · 16 min

L'étape 2 a laissé une réservation : arrêtez l'application, lancez `npm run reset`, puis relancez-la avec la même heure. Une recette complète prend 3 à 4 minutes.

```sh
npm run qa:commande
```

Le script affiche la commande `claude -p` qu'il lance : la consigne de déléguer à `qa-visiteur`, le schéma `qa/verdict.schema.json`, deux plafonds (`--max-turns 30`, `--max-budget-usd 4`), les outils permis et `--permission-mode dontAsk`. Il écrit `qa/verdict.json` et se termine avec le code 0 si tout est `ok`, 1 en cas d'`echec` ou d'`incomplet`, 2 si la recette n'a pas pu aboutir.

Plafond atteint (code 2) : relancez avec un plafond plus haut, par exemple `npm run qa:commande -- --tours 40` ou `-- --budget 6`. Si votre terminal retire le `--`, écrivez `--tours=40`. Un seul parcours : `-- --parcours 1`.

Puis la régression volontaire : `npm run sabotage`. Arrêtez l'application, qui tourne encore avec l'ancien code, lancez `npm run reset`, relancez-la avec la même heure, puis la recette du seul parcours 1 : `npm run qa:commande -- --parcours 1`.

> Le parcours 1 est en échec. Pars de la preuve de qa/verdict.json pour trouver la cause dans le code. Montre-la-moi et attends mon accord avant de corriger. Ensuite, corrige et lance npm test.

Arrêtez l'application, `npm run reset`, relancez-la, puis relancez la recette du parcours 1.

**Vérifiez :** après le sabotage, le parcours 1 est `echec` et la commande se termine avec le code 1 ; après la réparation, « Recette : ok » et le code 0.

**Attention :** `claude -p` charge les hooks et le `.mcp.json` du repo sans demande de confiance. Ne le lancez que dans un repo que vous avez lu.

### 4. Le programme · 12 min

Lisez `qa/agent-qa.mjs` : la même consigne, le même schéma et les mêmes plafonds, passés à `query()` de l'Agent SDK. Il utilise votre connexion Claude, sans clé d'API. Arrêtez l'application, `npm run reset`, relancez-la, puis lancez :

```sh
npm run qa:programme
```

Puis choisissez une suite avec Claude. Soit une page de rapport :

> Modifie qa/agent-qa.mjs pour qu'il écrive aussi une page qa/rapport/index.html : les trois parcours, leur verdict, leur preuve et un lien vers chaque capture qui existe vraiment dans qa/rapport/. Échappe tout le texte. Relance le programme et ouvre la page.

Soit un skill de projet `relecture-pr` qui relit une branche par rapport aux règles de `CLAUDE.md` et cite le fichier et la ligne de chaque écart.

Commitez ensuite le travail de l'atelier : `qa/parcours.md`, `.claude/`, `qa/agent-qa.mjs` et le test de la réparation.

**Vérifiez :** la page ne montre que des captures réelles et aucun parcours `ok` sans preuve ; après le commit, `git status` est propre, car `qa/rapport/` et `qa/verdict.json` sont ignorés par Git.
